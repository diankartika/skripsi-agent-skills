# Evaluation Criteria

## Purpose

Use these criteria to determine whether an observed interface
characteristic should be reported as a usability finding.

A finding should be based on observable evidence and a justified
relationship between the observation and a usability principle.

## 1. Observability

The issue must be supported by evidence that can be observed
from the provided interface.

Acceptable evidence includes:

- visible UI elements
- text and labels
- layout and visual hierarchy
- navigation structure
- visible system feedback
- visible interaction states
- observable inconsistencies

Do not report an issue based solely on assumptions about
hidden system behavior.

## 2. Heuristic Relevance

The observation must have a clear relationship to at least
one defined usability heuristic.

The evaluator should explain:

- which heuristic is affected
- what aspect of the interface relates to the heuristic
- why the relationship is relevant

Do not assign a heuristic merely because it appears superficially
related to the interface element.

## 3. User Impact

Consider how the observed issue can affect the user's interaction.

Potential impacts include:

- increased cognitive effort
- difficulty understanding the interface
- difficulty finding information
- difficulty completing an interaction
- increased likelihood of user error
- uncertainty about system state
- reduced efficiency

User impact should be described in relation to the observable
interface rather than assumed user behavior.

## 4. Evidence Sufficiency

A finding should contain enough evidence to explain the problem.

Prefer specific descriptions such as:

"The primary navigation contains two labels with similar wording,
making their destinations difficult to distinguish."

Avoid unsupported statements such as:

"The navigation is confusing."

## 5. Actionability

A finding should provide a recommendation that can reasonably
address the identified problem.

The recommendation should correspond directly to the observed
issue.

Avoid generic recommendations such as:

"Improve the UI."

## 6. Duplicate Findings

Do not report the same underlying usability problem multiple times.

When one interface characteristic affects multiple heuristics,
determine whether separate findings provide meaningful additional
information.

If the issues are substantially the same, report one primary
finding and identify the most relevant heuristic.

## 7. Personal Preference

Do not report a design as a usability problem solely because
it differs from the evaluator's aesthetic or personal preference.

A finding should be grounded in:

- usability principles
- observable evidence
- user impact
- established heuristic criteria

## 8. Uncertainty

When the available evidence is insufficient to establish a
finding, do not present the finding as certain.

The evaluator may indicate uncertainty when:

- relevant interaction behavior cannot be observed
- the screenshot does not provide enough context
- the issue depends on hidden functionality
- multiple interpretations are plausible

## Finding Qualification

Before including a finding, verify:

1. Is there observable evidence?
2. Is there a relevant heuristic?
3. Can the relationship between the evidence and heuristic
   be explained?
4. Is there a plausible user impact?
5. Is the recommendation specific and actionable?
6. Is the finding distinct from other findings?

If these conditions cannot be adequately satisfied, do not
report the observation as a confirmed usability finding.
